# May Monitor 默认持续监测配置安全审查

审查日期：2026-10-24，Asia/Shanghai。

本轮完成服务端、Agent、前端及构建来源的防御性审查，并修复确认的问题、增加隔离回归。结论限定于下述源码快照和**默认持续监测配置**。可选插件、远程控制和任意上游新版本不在这一结论的自动授权范围内。

本次修复以 `v0.1.0-rc.1` 作为首个 May Monitor 预发布版本发布；没有安装或部署。现有 Deploy 的 Komari 固定版本、生产实例、Cloudflare、私人归档、用户应用及 Route 的系统代理／TUN 状态均未变更。

## 2. 确认问题与处理

| 编号 | 问题与触发范围 | 处理和验证 |
| --- | --- | --- |
| F01 | 服务端／Agent 的旧 Go 依赖，以及前端直接和嵌套依赖有已知公告命中 | 按官方公告更新相关模块和锁文件；处理 Monaco 嵌套 DOMPurify；没有使用强制全量破坏性修复。最终扫描的剩余提示见第 4 节 |
| F02 | 已有 2FA 可用新注册的密钥覆盖；SQL 控制台未受敏感操作验证保护 | 已启用的因子必须先完成原有因子的停用验证；数据库更新增加条件保护。SQL 查询、执行和表枚举标记为敏感，默认关闭控制台；显式启用时用户会话仍须通过 2FA |
| F03 | 管理员会话删除、Agent Token／API Key 轮换后，既有 WebSocket 仍缓存原权限；临时分享也有长连接时效问题 | 收发消息时检查当前凭据；撤销后不能继续操作。RPC 逐请求复核分享有效期，普通公开数据流也复核私有站点／分享状态 |
| F04 | Agent 基本信息上报可修改可见性、备注、Token 等控制端字段 | 使用库存信息白名单；UUID 来自认证身份，Token、名称、分组、隐藏状态和账单等保留给管理员。验证正常库存更新仍可工作 |
| F05 | JSON-RPC、WebSocket 及 gzip 解压后的正文缺少一致上限 | JSON／解压后的应用消息限制 4 MiB，RPC 批量限制 100 条；鉴权辅助读正文也有上限。另有流式传输的独立限制，默认不开放远程文件能力 |
| F06 | 新旧密码均使用固定盐的单次 SHA-256 | 新写入改为随机盐、成本 12 的 bcrypt；密码先做 SHA-256 并编码，避免长密码被 bcrypt 截断。旧格式只保留成功登录后的升级路径，升级使用条件更新 |
| F07 | 主题切换等状态改变使用 GET；仅依赖 CORS 不能阻止简单跨站请求 | 主题切换、注销、2FA 注册生成改 POST；Cookie 修改操作增加独立请求边界。前后端调用同步修改，验证同源 POST 可用、旧 GET 和简单跨站请求不能修改状态 |
| F08 | 登录没有路由级尝试限制；默认信任转发地址会削弱按来源限制 | 每来源每分钟最多 10 次尝试、并发密码验证最多 4 个，来源记录最多 4096 项；过期释放。默认不信任转发头，实际代理地址须由操作方显式配置 |
| F09 | GitHub OAuth 状态不失效、可重复消费；QQ 回调放宽了状态匹配 | 三种提供者共用有容量上限、5 分钟有效、原子单次消费的状态处理；回调严格匹配。QQ 将状态保留在回调地址中，不再对缺失或不匹配状态放行。外部请求增加时限和正文界限，GitHub 客户端密钥从 URL 移至请求正文 |
| F10 | Agent 更新缺失摘要时放行；更新可沿用不安全证书选项和上游自动更新来源 | 缺少或不支持 SHA-256 摘要时拒绝安装；更新专用客户端始终验证 TLS 并拒绝不安全重定向。默认更新源改为自有 fork，自动更新默认关闭 |
| F11 | 持续监测默认携带完整远程管理和扩展能力 | 服务端 HTTP、RPC 及启动加载边界默认关闭命令、终端、文件、任意 SQL、插件、脚本通知、主题／原始页面 HTML、归档导入和调试能力。Agent 对应远程能力也默认关闭。不是仅隐藏前端菜单 |
| F12 | 远端 HTML 直接渲染、插件框架同时赋予脚本和同源权限；站点文字替换未转义 | 页脚及配置说明使用修复后的 DOMPurify；插件 iframe 移除同源权限；站点名称／说明转义，默认不注入原始自定义 HTML。DOM 合成测试保留格式并拒绝活动内容 |
| F13 | 未完成安装的首次启动向导允许匿名初始化及上传恢复 | 写操作要求私有初始化密钥；缺失或错误密钥不能创建账号。密钥只通过控制台链接的 fragment 获取，前端用请求头发送，完成后控制器关闭。首次归档导入也默认关闭，新安装默认私有站点 |
| F14 | Agent 正常传输的响应读取无上限，错误可能带 Token URL、响应内容或命令文本 | 正常 HTTP 响应和解压后 WebSocket 消息限制 4 MiB；核心传输错误不回显请求 URL、响应正文及命令文本。用合成秘密字符串验证错误输出不含该值 |
| F15 | 上游 Unix JavaScript 文件测试失败：`utf8` 编码参数被转换成权限 000 | 修正编码字符串的默认权限处理；原始快照复现失败，修复后通过，并保留原有路径逃逸／隔离测试。属于有效的可用性修复，没有放宽文件系统隔离 |
| F16 | 默认数据目录权限依赖宽松的目录创建模式 | 启动时将数据根设为 Unix 0700，拒绝符号链接数据根；创建私有子目录。外置数据库目录及系统 ACL 不据此宣称已被保护 |

供应链处理另外包括：隔离原有上游自动同步、自动提交、自动合并和发布工作流；旧安装脚本改为不可用的参考入口。新手动 CI 只检查代码，不发行、不部署；官方 Actions 固定完整 SHA，仓库权限只读。服务端要求选择自有前端仓库的完整提交，避免动态跟随开发分支。历史说明文件增加了 May 边界提示。

## 3. 默认能力边界

基础库存、指标上报、状态查看、配置管理和普通通知保留。未登录用户、Agent Token 和管理员／API Key 分别验证，Agent 不能调用管理员 RPC。

`MAY_MONITOR_ALLOW_REMOTE_CONTROL`、`MAY_MONITOR_ALLOW_DATABASE_CONSOLE`、`MAY_MONITOR_ALLOW_EXTENSIONS`、`MAY_MONITOR_ALLOW_ARCHIVE_IMPORT`、`MAY_MONITOR_ALLOW_DEBUG` 均默认关闭，只有操作系统环境中的精确值 `true` 可以启用。Web 设置和 API Key 不能替操作方改变这些能力开关。

重新启用可选能力会扩大受信任范围，需要单独验收。尤其不能把 JavaScript 兼容运行时当作操作系统沙箱，也不能把完整管理员 API Key 当作只读监控令牌。

首次安装密钥可由进程生成，或通过 `MAY_MONITOR_SETUP_TOKEN` 提供。控制台初始化链接必须私下保存，不能进入公开日志或工单；片段不会出现在 HTTP URL／Referer 中，API 不返回密钥。已安装实例不会重新开放初始化写入口。

## 4. 依赖扫描口径

Go 基线模块扫描命中服务端 39 条、Agent 18 条公告。这些是**模块版本匹配**，不等于相同数量的可远程利用路径。修复后 Agent 未命中已知公告；服务端保留 `GO-2026-5932` 的模块提示，涉及不再维护的 `golang.org/x/crypto/openpgp` 系列。该包没有修复版本，本程序依赖图没有导入它，也没有对应可达调用。没有屏蔽该提示，后续差异应重新检查导入图。

前端完整 npm 扫描从基线 18 项降为 0 项；包含新增测试依赖后再次扫描。此结果只针对扫描时官方数据库已知公告，不是未知漏洞的证明。

参考：[Go 官方漏洞数据库](https://vuln.go.dev/)、[npm audit 文档](https://docs.npmjs.com/cli/v11/commands/npm-audit/)、[OpenPGP 上游说明](https://go.dev/issue/44226)。更新摘要来源于受 TLS 保护的发行 API，不能代替独立发行签名。

## 6. 后续接入要求

以下属于生产接入任务，本轮没有执行：

1. 为 Deploy 建立范围受限的只读监控凭据和显式部署流程，不能复用完整管理员 Key。
2. 在隔离目标机验证服务账号、配置和备份权限、外置数据库目录、TLS、反向代理信任与连接／带宽限制；初始化密钥由受信任操作链交付。
3. 记录空闲、正常监测、断线重连与长时间留存的 CPU、常驻内存和磁盘曲线。当前大小／并发限制及功能测试不能代替性能实测。
4. 对真实 SSO 提供者、可选插件／脚本和远程控制分别验收。QQ 聚合服务能否正确保留回调状态尚未连真实服务确认，不应提前启用。
5. 明确首个 May 发行的兼容版本、构建来源／摘要与签名、部署升级和旧数据恢复／回退证据，再决定是否替换既有 Komari。上游后续变更始终按需审查。

本轮审查和默认配置修复完成，不代表已经完成上述生产接入，也不授权自动安装或迁移现有服务。

## v0.1.0-rc.1 发布附录

本版本以以上原始审查快照为基础，仅增加发布所需的版本与构建元数据、May CLI／附件命名及可控构建时间；没有重新启用被关闭的能力。原始审查清单的 SHA-256 仍作为历史证据，不能替代发行源码的提交 ID。

三个发行仓库、准确提交、前端锁定提交、编译器及附件摘要分别见 Release 中的 `release-manifest.json` 与 `SHA256SUMS`。相关源码改动已补测。Linux 服务端使用 musl 静态链接，避免要求部署主机拥有构建机较新的 glibc；ARM64 产物需要区别交叉编译与原生运行验证。

本版本是预发布，不包含生产部署或旧 Komari 迁移授权；默认关闭远程控制、扩展及自动更新。
