# 指标、历史、探测与告警

基线：May Monitor 0.1.0。安装与身份见[运维教程](OPERATIONS.zh-CN.md)，外部投递见[邮件](EMAIL.zh-CN.md)。May Status 的视觉评级与 May Route 的代理故障切换不是本页告警策略。

## 数据口径

| 数据 | 含义 | 常见误读 |
| --- | --- | --- |
| CPU | 主机采集的使用百分比 | 不是系统 load 的百分化。 |
| 系统负载 | 与逻辑核心数一起解释的 load | 不能用固定 0–100% 轴表达。 |
| 内存／磁盘 | 采集口径下的用量、总量和比例 | 缓存选项变化会改变口径，不应跨口径比较。 |
| 流量速率／累计 | Agent 所选网卡及统计周期的数据 | 不是云服务商账单的权威替代。 |
| 在线 | 当前 WS 连接或未过期回退租约 | 不保证报告新鲜，也不保证某条代理线路可用。 |
| 历史 | 持久化及分层汇总的观测 | 空洞不能补成零负载。 |

先核对采样时间，再看在线状态。第一次采集、离线、报告过期、无效数据和 Server 不可读取应分别处理。系统时间变化、连接重建和服务维护都可能影响采样；排错记录应包含准确时间和阶段。

## 建立探测

在管理端配置明确的任务、目标、协议和参与节点。只对自己允许探测的目标设置合理频率；不因页面能显示图表就将任务应用到所有节点。

- ICMP 为对应探测的往返结果，需要操作系统允许。
- TCP 关注指定目标端口建连，不证明应用鉴权或文件可下载。
- HTTP 关注所定义请求阶段，与 TLS、拨号和完整下载耗时不是同一个指标。

从 VPS 探测广东的结果与广东用户经过入口、落地访问某站点的完整路径不同；不能把数字除以二当作单程时延，也不能据此决定 Route 一定应切换。

## 历史与失败比例

`ping.loss` 表示任务探测失败比例。按时间桶的探测次数加权；不能对降采样后一个延迟值判断整桶丢包。它不是所有业务包的真实丢包率。

目标或任务身份改变后旧样本不能混入新告警窗口。缺失数据保持缺失，100% 失败正常展示，不为让曲线好看而插值成成功。主题缺少需要的能力时显示不可用，不静默回退旧接口或估算比例。

历史按分钟、五分钟和小时层级管理。页面可选七天不保证服务器实际保留七天的细粒度样本。调整保留策略前核对最老／最新时间、数据行数、DB／WAL 大小和磁盘余量；不要用旧单一保留字段推导全部窗口。

## 设置规则

管理端「监测与告警」保存规则与通知渠道。当前策略最多 32 条规则、合计 100 个节点；每条规则需明确节点范围。先保持通知关闭，确认状态变化正确，再启用实际渠道。

| 规则 | 范围与阈值 | 恢复口径 |
| --- | --- | --- |
| 离线 | 节点，无探测任务阈值 | 取得新的有效恢复证据。 |
| 延迟 | 指定任务，1–3000 ms | 回到设定阈值的 80% 以内。 |
| 探测失败率 | 指定任务，1–100%，窗口至少 3 | 回到设定阈值的一半以内。 |
| CPU／内存／磁盘 | 1–100%，不引用探测任务 | 回到阈值减 5 个百分点以内。 |

每条规则的异常／恢复确认次数为 1–10，窗口为 1–20，冷却为 0–86400 秒，静默最长至未来七天。地区名称帮助组织规则，不能自动证明线路归属或为每个地区选择合适阈值。探测协议、目标和正常路径不同，应分别设计。

窗口与连续确认防止一次波动直接外发。缺失、过期或无效样本不应记为健康恢复。修改任务、节点或条件后核对当前规则的新证据，不能用旧窗口补足确认。

## 通知和事件

支持不发送、本地 HTTP 和邮件。回环 HTTP 仅接受字面回环 IP，用于明确部署的本地接收器，不是任意公网 webhook。邮件使用独立私密配置和 TLS。

事件按稳定 ID 管理故障和恢复、冷却、静默与有界重试。单次投递成功表示发送器取得相应接收证据；SMTP 接受邮件不保证收件箱最终到达，确认丢失可能导致同一 ID 重复。重试不放宽 TLS，也不自动换渠道。

启用后观察一次可控的故障与恢复，核对事件、时间、通知结果和静默行为。没有真实渠道验收时只能报告本地夹具通过，不能宣称用户已收到通知。不要对生产节点制造失联以代替隔离测试。

## 独立 watchdog

Server 自己无法可靠通知整台宿主机掉电，watchdog 应放另一台主机。它使用受限只读授权和已核验 UUID，先证明可读取，再累计失联和恢复。鉴权失败、TLS 错误、来源不符及报告过期分开记录；令牌到期不是 Server 必然宕机。

watchdog 不改代理、不恢复旧监控、不接管 Agent，也不替代每个节点的告警。Server 和 watchdog 的邮件配置各自独立，避免 Server 故障时发信仍依赖同一台机器。

## 资源与验收

按同阶段比较预热后的中位数、P95、峰值及增长，分别记录进程 RSS／CPU、主 DB、WAL、报告年龄、重连和样本缺口。保留计划故障和宿主维护标记，不能静默删除异常来得到通过结果。

M5 的冻结候选长测与稳定发行的单元／夹具／运行观察是不同证据。完整报告与未能反向复现的历史异常见[长测记录](https://github.com/mxh110708/may-vps-deploy/blob/main/docs/MONITOR-M4-M5-2026-10-25.zh-CN.md)。
