# 邮件告警与独立检查

邮件用于规则故障／恢复事件及独立 watchdog。默认不发信；不会搜索本机邮箱、复用管理员密码或自动推断收件人。Web 的“监测与告警 → 通知渠道”可以选择不发送、本地 HTTP 接收器或邮件。本地接收器仍只允许字面回环 IP。

## 配置 SMTP

由服务器操作者在进程工作目录中创建 `notification-smtp.json`。Deploy 管理的 Server 工作目录是 `/var/lib/may-monitor-server`；独立 watchdog 使用自己的工作目录和配置副本。JSON 格式如下，所有值均为占位符：

```json
{
  "host": "smtp.example.com",
  "port": 465,
  "security": "tls",
  "username": "sender@example.com",
  "password": "<SMTP_AUTH_CODE>",
  "from": "sender@example.com",
  "to": ["recipient@example.com"]
}
```

必须使用发信服务提供的 SMTP 账户／专用授权码。支持隐式 TLS 的 465 端口，或 `security: "starttls"` 配合 587 端口；587 必须成功升级到 TLS 才认证。拒绝明文回退、无效证书、错误主机名和低于 TLS 1.2 的连接。发件地址应符合服务商的授权要求，接收地址最多五个；不支持显示名称、地址列表字符串或邮件头换行。

文件由运行进程的专用账户所有，权限设为 `0600`，上层目录保持私有。若通过其他秘密管理方式提供配置，可以使用 `MAY_MONITOR_SMTP_CONFIG` 指定绝对路径；不能指向符号链接。部署配置时不要使用会记录凭据的终端命令历史，也不要将该文件提交到 Git。普通管理员设置、告警策略、只读摘要及错误信息均不会返回 SMTP 用户、密码或收件人。

主机必须是 DNS 域名；实际解析结果全部为公网地址后才连接到已解析的地址，TLS 仍校验原域名。不使用系统代理，不接受内网 SMTP、中继回环、云元数据地址或混合内外网 DNS。需要企业内网邮件服务时应单独审查，不能关闭校验来接入。

配置文件在投递时重新读取，无需为了换授权码重启 Server；已经进入发送的事件使用该次读取的配置。先保持通知渠道关闭，核对发件人和收件人后再明确选择邮件并保存策略。规则未启用时不会因配置文件出现而发信。

## 状态、重试与恢复

管理员界面区分“尚未配置”“配置无效／权限不安全”和“配置就绪”。配置就绪只说明本机校验通过，不表示服务商认证或收件箱投递成功。未配置时规则继续评估，但不发邮件；未配置真实发信时，只能记录本地夹具验收，不能声称真实邮箱已收到通知。

邮件复用告警引擎的事件 ID、连续确认、冷却、静默和最多三次尝试。故障和恢复各有事件；重试保持相同 `Message-ID` 和 `X-May-Event-ID`。SMTP 接受 `DATA` 后即记录发送成功，不因后续关闭连接失败再次投递。若 SMTP 已接收但客户端在获得回执前断开，仍可能出现同一 ID 的重复邮件；服务商回执也不保证邮件没有进入垃圾箱。

单次发送最多十秒；DNS、TLS、认证及发送失败只记录类别，不保留服务商响应正文。一次配置错误不会放宽 TLS 或转用其他渠道。现有队列及事件历史仍有数量上限，禁用通知不停止规则状态评估。

## 独立主机

watchdog JSON 增加 `"delivery": "email"` 即使用相同邮件发送器；`"delivery": "none"` 表示只检查和保存状态。Server 与 watchdog 不共享本机文件，应分别安装专用配置，避免 Server 整机失联时邮件也依赖该机器。

watchdog 使用专用只读授权和已核验的 Server UUID，不使用管理员凭据。当前服务只有一份读取授权，Deploy 和 watchdog 共用其值及有效范围；轮换或续期后两端都要更新。状态文件有内核互斥锁，同一文件不能运行两个检查进程；正常退出或进程异常结束后锁自动释放，不需要删除锁文件。

本版本支持 Linux watchdog。真实外发的收件人、授权码、邮件服务可达性及投递结果，需要操作者配置后另行验证。本地 TLS SMTP 夹具验收不能当成真实邮箱已收到邮件。
